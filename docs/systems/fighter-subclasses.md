# Fighter subclasses

How this system works today: subclass-specific notes for the Rune Knight and Samurai (the other Fighter subclasses are described where their mechanics live — mostly action-economy.md).

> Moved verbatim out of CLAUDE.md on 2026-11-14 so it loads when needed instead of every turn. **This file is now the home for this material — update it here.** The standing rules that apply across systems stay in CLAUDE.md under "Character sheet rules"; what is still missing is in CLAUDE.md under "Frontend Not Yet Built".

- **Rune Knight (Fighter, 5e only — the 2024 PHB ships no Rune Knight) — BUILT to level 20 (pending user QA).** **Feature-text correction (QA):** the stored `Giant's Might` blurb claimed "you can grapple Large creatures" and `Runic Juggernaut`'s claimed "grapple creatures of Huge size or smaller". Neither clause is in the feature. Grappling is governed by SIZE — no more than one size larger than you — so a Medium character **already** reaches Large, and what Giant's Might really does is make you Large, moving the ceiling to Huge (Huge → Gargantuan at 18). The blurbs therefore granted nothing while teaching a baseline one size too low, **and a player reading them concluded exactly that** — they reported the new Grapple card as wrong because the feature text said otherwise. Corrected in `subclassData/fighter.js`: the invented clause is gone, the advantage is narrowed to "Strength checks and Strength **saving throws**" (matching what `grants` returns — the old "saving throws" contradicted the tags the sheet draws from it), the once-per-turn/unarmed-strike scope of the 1d6 is stated, and Runic Juggernaut's real second clause (+5 ft reach while Huge, already implemented as `reachBonus`) replaces the grapple line. Guarded by tests in `activeEffects.test.js`, since these strings are read back out of SUBCLASS_DATA by the Defenses and save-features panels. Built: **Giant's Might** (bonus-action card + PB/long-rest pool + the active-effect toggle + the scaling damage rider + the grown size) and **Runic Shield** (reaction card + PB/long-rest pool), both reset by the backend long rest (rows in `_REST_RESOURCES`); and **Rune Carving** — a `levelChoicesData` pool of the 6 runes (`runesData.js`), 2→3→4→5 known at levels 3/7/10/15, Hill gated at L7 and Storm at L15 via option `minLevel`, swap-one-per-Fighter-level, stored in `character_data.runes`, with the save DC (8 + PB + CON) on the choice's `derived` line and the known runes shown by `KnownOptionsBlock`. It cost NO new component code. *(QA found the pick never happened at all — a Rune Knight leveled to 3 and was simply never asked. A character who leveled before this existed knows no runes and is offered the owed slots on the sheet.)* Also built: **rune → item assignment** (`character_data.rune_items`, the control on the Items-tab weapon/armor/shield rows via `RuneCarvingControl`; see the schema note — knowing a rune grants nothing, `activeRunes()` requires carved AND equipped), **Channel Rune** (six `hidden(ctx)` rest rows + six Action Economy cards generated from `RUNE_OPTIONS`, one per rune, each with its own counter, 1/short-or-long rest → 2 from **Master of Runes** at L15; the Fire Rune's rides on a weapon attack so it ATTACHES to the attack cards via `ATTACHED_FEATURES` with a CON-based save DC — and deliberately contributes NO damage term to that card's total, since its 2d6 lands only on the swing where you spend the use; **Frost's, Hill's and Storm's are ACTIVE EFFECTS** (Frost's +2 reaches the numbers; Hill's BPS resistance reaches the Defenses card; Storm adds the Prophetic State reaction) — Frost changes numbers the sheet already prints, so its card carries the start/End toggle and its +2 reaches the STR/CON saves and Athletics — a bare Use counter left the bonus living nowhere. A rune opts in with `channel.activeEffect`; the one-shot runes carry no key and are unchanged), and **5 of the 6 rune passives**: skill advantage (Cloud/Frost/Stone/Storm) through the new `skills/skillAdvantage.js` — the `SKILL_ADVANTAGE_SOURCES` extraction that had been flagged, which absorbed the Champion hardcode out of `CharacterDetail` — and Hill Rune's poison resistance (`defenses.js`) + advantage on saves vs. poisoned (`saveFeatures.js`). Both of those tables gained an optional **`applies(ctx)`** predicate, the escape hatch for a gate the declarative class/subclass/level keys can't express (a rune depends on `character_data`, not on level).
  **Stone's darkvision 120 ft is now real** — QA asked where the sheet states the range and the answer was nowhere, so it drove the `senses/senses.js` module (see the Senses bullet above) and is a `passive.vision` data row. **The Fire Rune passive is real too, and its stored text was wrong:** RAW DOUBLES your proficiency bonus on a check using a tool you're proficient with (the old "add your PB" granted nothing). `inventory/toolChecks.js` (`toolCheckProficiency`) answers the one fixed part of a tool check — the proficiency term — and the Tools sub-tab banner prints it (`tool-check-proficiency`: "+3 (your proficiency bonus)" / "+6 (… doubled by Fire Rune, carved on …)"); there's no per-tool number because a tool check has no fixed ability. A source table, so Artificer Tool Expertise is its second row. Still prose: **Storm's can't-be-surprised** (no surprise state — user's call 2026-10-26: deliberately deferred until enough features need one; ~7 already reference surprise: Alert 5e, Feral Instinct, Watchers, Assassinate, Death Strike, Thief's Reflexes). **Bonus Proficiencies — BUILT** as a row in the existing fixed-grant table `SUBCLASS_PROF_GRANTS_5E` (`inventoryProficiencies.js`, the Hexblade's): smith's tools reach the Tools banner via `gatherProficiencies`, and the new `languages` key is read by `subclassFixedLanguages()` → the languages panel's "From Subclass" group + the Linguist/subclass-grant pickers' already-known sets. Derived, never stored, so no migration. **Runic Juggernaut's +5 ft reach is real:** `weaponReach(weapon, {bonusFt, source})` in inventoryData, resolved once per row in `getAttacks` (`row.reach`, needs the new `characterData` arg) and given to the unarmed row in `buildActionEconomy`; rendered by the shared **`WeaponReachBadge`** on the Items-tab row (`attack-reach-{uid}`) and the Action Economy card (`ae-reach-{key}`), only when reach ≠ 5 ft — so it also shows "Reach 10 ft" on any Reach-property weapon for every class. The effect's `grants` carries `reachSource` so the badge names "Runic Juggernaut". Juggernaut's Huge is RAW optional ("can"), so from 18 the Giant's Might card's toggle carries a **Large / Huge choice** (`ae-effect-choice-giants_might-{Large|Huge}`), stored as `character_data.giants_might_size` (unset = Huge) and read by `sizeAt(level, characterData)` — so size, the +5 ft reach (Huge only) and the card text all follow it. The mechanism is generic: an effect definition may carry `choice: {key, label, options(level), defaultValue}`, resolved by `activeEffectChoice()` onto the entry's `effectChoice`, and `grants`/`summary` now take `(level, characterData)`. Great Stature's height roll stays narrative text in the feature (user's call: never computed). **Producer/consumer guard:** `classData/runeFieldReaders.test.js` fails if any `RUNE_OPTIONS.passive`/`.channel` field or active-effect `grants` field lacks a named reader file that references it (it found and removed three dead fields: `passive.saveAdvantage`, `passive.note`, `grants.attackDie`; Hill's Defenses row now reads `passive.resistances`, Giant's Might's save row reads `grants.advantageSaves`). Text corrected at the source in `subclassData/fighter.js` and pinned in `runesData.test.js`: Runic Shield (use the NEW roll), Great Stature (a one-time 3d4-inch roll; the invented "equipment adjusts" clause removed).
  **Deliberate scope limit on rune-bearing objects:** RAW a rune may be inscribed on "a weapon, a suit of armor, a shield, a piece of jewelry, or something else you can wear or hold in a hand", but the assignment will offer **weapons, armor and shields only** — the only wearable/holdable things the inventory models as equippable. **Revisit jewelry and other worn objects when items/armor get more robust** (they live in `adventuring_gear`/`magic_items` today with no worn state).
