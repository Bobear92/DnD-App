# Action Economy

How this system works today: the Action Economy tab: buckets, weapon attack cards, riders, attached features, combos, spell cards, and the Fighter subclass entries wired into it.

> Moved verbatim out of CLAUDE.md on 2026-11-14 so it loads when needed instead of every turn. **This file is now the home for this material — update it here.** The standing rules that apply across systems stay in CLAUDE.md under "Character sheet rules"; what is still missing is in [docs/backlog.md](../backlog.md).

## Notes on a weapon attack card — where each kind lives

A weapon attack card can carry three kinds of extra line. Put a new one in the right place rather than adding a field:

| Kind | Where it is defined | How it renders |
|---|---|---|
| **Rules text that applies when you attack** (a rider) | a row in `ATTACK_RIDERS` — `{source, scope, charClass?, subclass?, minLevel?, edition?, applies?, text}` | `RiderLine`: the name, rules text on click (`ae-rider-{slug}` → `…-text`) |
| **…that ALSO belongs on the item you attack with** | a row in `EQUIPMENT_FEATURES` (`inventory/equipmentFeatures.js`) with `attackScope` — `ATTACK_RIDERS` spreads `attackCardFeatures()` in | the same rider on the card, and the same note on the item's Items-tab row |
| **A number or a link** (crit range, the Hex Warrior ability note, spacing, loading) | a field on the entry, set in the weapon loop | its own line; these are not rules text and are not riders |

**Rider scopes** (`matchesRiderScope`): `melee` / `ranged` / `all` go by the kind of ATTACK (an unarmed strike is a melee
attack); `weapon` / `meleeWeapon` require a real weapon and never match an unarmed strike. The last two use the same names,
with the same meaning, as `ITEM_SCOPES` on the Items tab.

**Shared today via `attackScope`:** Savage Attacks and Great Weapon Master's bonus attack (`meleeWeapon`), Eldritch Strike and
2024 Remarkable Athlete's move (`weapon`). They were previously authored twice — the table row for the Items tab plus a
bespoke entry field each (`savageAttacksNote`, `greatWeaponMasterNote`, `eldritchStrikeNote`, `remarkableMoveNote`) with a
hand-written render branch in the tab. Those fields are gone; do not add a per-note field again.
`combat/attackCardFeatures.test.js` pins that the item row and the attack card show the same text.

- Action Economy tab — **framework + Fighter (5e + 2024) built** (vertical slice). **RULE: "…you can use your reaction …" means a card in the REACTIONS tab** (feats: author a `reaction` action effect — Shield Master's Interpose Shield was a prose note, found in QA; curated class/subclass features: a guard test fails any mapped feature whose text grants a reaction but has no `tab:'reaction'` entry. **That guard reads SUBCLASS_DATA feature descriptions ONLY, which is a real blind spot** — a POOL OPTION's rules text lives in its own module, so Rune Carving passed it while saying nothing but "a Channel Rune effect" and the per-rune reaction prose sat unscanned in `runesData` (found in QA by a player reading the rune list, not by the suite). Its **option-pool sibling guard** closes that: it scans each option's PLAYER-FACING text — including the parenthetical cost, "Channel Rune (reaction, …)", since a pool states the cost as structured data and the sentence never says "use your reaction" — and checks BEHAVIOURALLY that a reaction card appears for a character actually holding that option. Pools the tab does not cover yet are NAMED in its PENDING list (Battle Master Parry + Riposte, both editions), never silently skipped. Both guards exclude "its Reaction": Commander's Strike spends an ALLY's, which is no card on this sheet. **When a feature's real text lives outside the table a guard reads, the guard does not cover it** — check that before trusting a green suite on a new pool). **RULE: "If you take the Attack action, you can use a bonus action …" is an Action + Bonus COMBO, never a lone bonus action** — recognise it from the text. Feat `action` effects are routed automatically by `isAttackActionBonus` (+ per-feat `ATTACK_ACTION_COMBO_GATES`: Polearm Master's opener weapon, Shield Master's shield warning); curated class/subclass entries are guarded by a test that fails any `tab:'bonus'` entry with that wording. Un-wired instances waiting on their class: War Priest, Sudden Strike, Monk Martial Arts/Flurry/Searing Arc Strike, Commander's Strike. Auto-derived sources (weapon attacks, spells-by-casting-time, Two-Weapon Fighting, universal action menu) work for ALL classes; the curated class-feature→action-economy map (`actionEconomyData.js`) currently covers Fighter only. **Subclass features now have their own map** (`SUBCLASS_FEATURE_ACTIONS_*`, level-gated from SUBCLASS_DATA — wired: Eldritch Knight Weapon Bond + the War Magic combo + Arcane Charge rider as curated blocks; Arcane Archer Arcane Shot + Curving Shot; Cavalier Unwavering Mark (split across two surfaces, below) + Warding Maneuver (reaction) + Ferocious Charger; Echo Knight Manifest Echo (bonus, computed echo AC) + Unleash Incarnation (**attached to the melee attack cards**, see below) + Echo Avatar + Shadow Martyr + Reclaim Potential (computed temp HP); Psi Warrior's six powers, below; **Rune Knight** Giant's Might — the first entry carrying an **`activeEffect`** key, so its card renders the active-effect toggle instead of the plain Use control — and Runic Shield).  **A subclass feature name may map to a SINGLE entry or an ARRAY of them** — some features bundle several powers at different costs under one name, and one card would have to pick a single cost badge and misstate the rest. The Psi Warrior drove it: `Psionic Power` is a reaction (Protective Field), an action (Telekinetic Movement) and an attack rider (Psionic Strike) at once, and `Telekinetic Adept` is a bonus action (Psi-Powered Leap) plus a second rider (Telekinetic Thrust). Array members carry their own `name`; a single entry still takes the feature name or its `displayName`. Its pool also gets a read-only **`PsionicEnergyPanel`** in the Features tab (Fighter config `subclassPanels['Psi Warrior']`, the same slot Battle Master and Eldritch Knight use): the pool DEFINITION — `{total} × {die}`, "twice your proficiency bonus", the next die-growth level in words via `nextPsionicDieStep`, an echoed unspent count, and the strike/save-DC rolls that fold in INT. Deliberately has no Use controls: spending already lives on the rest tracker and the action cards, and a third mutation point for one counter is how surfaces drift. Psi Warrior is also the app's first **one pool, many consumers** resource — five entries share one `psionic_energy_used` key while the three free-once-per-rest powers each carry their own small charge key — and its numbers come from `psiWarriorData.js`, never the stored feature blurbs, which are wrong in three places (a flat "d6" instead of the d6→d12 scaling, "fly speed equal to" instead of twice walking speed, and Telekinetic Movement called a bonus action when RAW is an action). It also drove the two ways one Use control can touch a SECOND resource row — deliberately separate fields, since they are opposite operations: **`fallbackResourceKey`** (entry) / **`fallbackKey`** (class-config row) = FREE-USE-THEN-PAY, where Use spends the row's own charge while it lasts and then spends the named pool, disabling only when BOTH are empty (Telekinetic Movement / Psi-Powered Leap / Bulwark of Force are each free once per rest, then cost a die — found in QA, where a spent free use left "0 / 1 remaining" and a dead button while four legal uses remained); and **`restoresResourceKey`** / **`restoresKey`** = SPEND-TO-RESTORE, one atomic patch spending the row's charge and handing a use back to the named pool (the bonus-action "regain one expended Psionic Energy die", which the backend had been resetting on every rest while the UI gave nobody a way to spend it). The regain is **the one sanctioned exception to "a player never restores a resource"** — the restore IS the feature firing, gated behind its own once-per-rest charge — and carries **`hidden(ctx)`** (both surfaces) so it disappears while the pool is full rather than offering a button that does nothing. A two-cost control also LABELS each count ("Free use 1 / 1 · Psionic Energy Dice 4 / 4"): a bare "1 / 1" beside a feature that also spends a shared pool reads as "you can do this once". Authored once for both editions, since the 2024 revision renames nothing and moves no level. Its L18 Telekinetic Master became **two cards, one of them a COMBO** — a `Cast Telekinesis` action card, plus a `Telekinetic Master` entry in the **`action+bonus`** bucket — after QA found the original single card badged 'bonus action' while its headline half, casting the spell, is an action. **Why a combo and not a lone bonus action:** RAW telekinesis is exerted *as your action each round*, so the bonus attack only ever happens on a turn whose action IS telekinesis (on the first turn the action casts it — you are concentrating from that moment, so the attack is already live; after that the action re-exerts it). Filed under `bonus` the card sat alone in the Bonus Actions tab with nothing naming the action that enables it, which is not something a player can act on. It carries **`telekineticAttack: true`**, which builds two halves. The `Action` half is a normal `subAttacks` row naming Telekinesis; it is not an attack, so it takes `detail` instead of to-hit/damage (the Tavern Brawler Grapple shape). The `Bonus` half is the new bit: **`bonusEntries` — REFERENCES to the real weapon entries in the Actions bucket, rendered by the tab as full nested attack cards**, not summary rows. QA drove this: the bonus attack is an *ordinary weapon attack*, so taking it needs the range band, Psionic Strike's Use control, the Sharpshooter toggle, spacing and ammunition — none of which a `{name, toHit, damage}` row can show. They are references and deliberately not copies, so anything attached to a weapon later in the pipeline (Psionic Strike/Telekinetic Thrust from earlier subclass features, the ATTACK_RIDERS applied at the very end) is picked up free rather than frozen mid-build; the tab **prefixes the key at RENDER time** (`{comboKey}-bonus-{weaponKey}`) so the nested copy's testids can't collide with the same weapon's own Actions-tab card while the entry stays live until drawn. Unlike Unwavering Mark the rows are `scope`-free (RAW says "a weapon attack", so a bow and an unarmed strike both qualify) and fold in NO damage bonus, so each mirrors the normal attack exactly. Its concentration gate is TEXT on the card rather than a filter, since the app models no concentration state (the line Rage and durations sit behind). The at-will *telekinesis* itself now lives in the Spells tab's Subclass source — see `subclassSpells.js` below. **Extra damage is FOLDED INTO the card's one damage number** — `applyDamageAdditions(view, additions)` → `{damage, damageBreakdown}`, feeding the same clickable `AttackNumber` the to-hit uses, so an attack shows ONE damage value with the math a click behind it. It used to print the plain swing plus a second "on a hit" total beneath it; QA reported that as "doubled damage", since both lines opened with the same string and neither said which to use. An addition of the weapon's own type (or an untyped one, which RAW means weapon damage) joins the DICE GROUP — `1d8 + 1d6 + 4 Piercing`, one roll — rather than trailing after the type word; a different type still keeps its own term, because piercing and fire are rolled and resisted separately. Dice are never summed into one die. **What may be folded in is narrower than what may be mentioned**: only damage that is *currently happening*, which today means an `active_effects` toggle the player has switched ON — `ATTACK_RIDERS.damage(row, ctx)`, i.e. **Giant's Might** alone (weapon-typed via `weaponDamageType`, scaling 1d6→1d10). Damage that costs a spend decided AFTER the hit stays out and lives in its feature's own block instead, where the number is still on the card beside the Use control that pays for it: the **Fire Rune**'s 2d6 and — as of this QA pass — **Psionic Strike**'s die + INT force, which had been inflating every swing a Psi Warrior might never pay for. So `ATTACHED_FEATURES.damage` currently has no authors; declare one only for damage that needs no in-the-moment choice. This is the standing Sneak Attack/Divine Smite rule narrowed, not lifted — what changed is that an active effect is a conditional the app actually knows about. Every folded-in term names its source in the breakdown (a number that grew because an effect is running would otherwise read as a bug in the weapon damage) plus its optional **`when`** — Giant's Might says "once per turn", since the printed number is per-attack. The data layer hands the card a LIST (`entry.damageAdditions`), not a finished string, and the card folds it into the damage it is CURRENTLY showing — a baked-in total would go stale the moment the Great Weapon Master / Sharpshooter toggle rewrites the damage. Ordering matters: the collection pass runs LAST, after ATTACK_RIDERS, since a rider is attached after the features are. **`attachedFeatures` is the generic "limited-use feature that rides on THIS attack" slot** — an array on a weapon-attack entry of `{key, name, note, resourceKey}`, rendered by `AttachedFeatureBlock` inside that attack's card with its own Use control (`ae-attached-{slug}-{entryKey}`). The control sits INSIDE the block, never at the card's top-right, so the remaining count reads as the feature's and not the weapon's ("5 / 5 remaining" beside a longsword claims the longsword has five uses). **It is now a data table, `ATTACHED_FEATURES`** — `{name, scope:'melee'|'ranged'|'all', resourceKey?, note(row, ctx)}`, opted into by a subclass entry's **`attachedAs: '<name>'`** — extracted at the SECOND consumer, the same consolidation trigger that produced ATTACK_RIDERS/ENTRY_RIDERS. When no attack matches the scope, the entry falls through to its standalone card, so the feature never vanishes (the Arcane Shot / Weapon Bond fallback shape). Authored: **Unleash Incarnation** (Echo Knight L3+, melee) — found in QA sitting in the No Action tab, where a feature you reach for mid-Attack-action is unfindable; it attaches to every melee attack row (`e.melee`, so an unarmed strike qualifies) with the weapon named in the note, so a bow-only Echo Knight never loses it. **Psionic Strike** (Psi Warrior L3+) takes `scope:'all'` — RAW keys on "a weapon attack", not a melee one, so a bow qualifies; an unarmed strike does too, which is why a bare-handed Psi Warrior keeps it on that card instead of falling back. **Fire Rune** (Rune Knight) is the counter-example for `damage`, and the line it draws: it deliberately declares NONE, so its 2d6 fire never joins the card's damage. The fire is not a property of the weapon — it lands only on the swing where you spend a Channel Rune use to summon the shackles, a choice made after the hit and never recorded — so it stays prose in the note beside the Use control that invokes it. **Psionic Strike is now the same call** (its `damage` spec was removed in QA): spending a Psionic Energy die is the same after-the-hit choice, and folding it in claimed force damage on every swing. Declare `damage` only for extra damage that needs no in-the-moment choice. **Telekinetic Thrust** (Psi Warrior L7+) carries no `resourceKey` at all: it costs nothing and fires on a Psionic Strike hit, so it rides the same cards rather than taking a card of its own. Arcane Shot deliberately keeps its own richer `arcaneShot` block (an options menu + a save DC, neither expressible here); fold that into `attachedFeatures` if a second rich one appears rather than writing another block. A subclass entry may now carry the same **`compute({characterData, level, scores})`** the racial map has — Ferocious Charger's Strength save DC scales with level and STR, so a fixed string would show the wrong number to everyone but one character. A `compute` may return a **`saveDc: {label, breakdown}`** instead of writing the arithmetic into `detail`: the tab renders it as a clickable `BreakdownValue` (`ae-save-dc-{key}` → `ae-save-dc-breakdown-{key}`), the same treatment the Arcane Shot DC gets. Ferocious Charger used to inline "DC 15 = 8 + PB +5 + STR +2" mid-sentence, which made the rules text unreadable for math nobody needs until they question the number. **Cavalier also demonstrates riding on a UNIVERSAL entry**: Hold the Line (L10) changes what the shared Opportunity Attack reaction does rather than adding an action, so it attaches as a `rider` on `universal:Opportunity Attack` (the Arcane Charge-on-Action-Surge shape). That block must run AFTER the universal menu is pushed, since that's what creates the entry it attaches to. **Vigilant Defender (L18) is the counter-example, and the line between the two:** it grants a whole SEPARATE reaction (once on every other creature's turn, not spending your normal one), so it is its OWN entry carrying **`extraReaction: true`**, which the tab renders in a bordered **"Extra reactions — on other creatures' turns"** section (`ae-extra-reactions`) below the normal groups. As a rider it was invisible — the Reactions tab showed a lone Opportunity Attack and nothing told the player they had a second reaction economy. Rule of thumb: a rider MODIFIES an action you already had; a feature that ADDS one gets an entry. **Arcane Shot demonstrates the "attach to the attack it rides on" shape**: rather than a free-floating No Action entry, a qualifying shortbow/longbow attack entry carries an `arcaneShot` payload (cost, save DC, each known option with its description) plus the shared `arcane_shot_used` resourceKey, and the tab renders it as a block inside that weapon's card with the Use control in it — so the option is read off the same card as the attack. It falls back to a standalone entry only when no bow is equipped (RAW excludes crossbows), so the feature never vanishes. **Unwavering Mark demonstrates SPLITTING one feature across two surfaces by cost** — it is two mechanics at two prices, and one card could only lie about one of them. *Marking* is free, unlimited and fires on a melee weapon hit, so it attaches as a **rider on every melee attack card** (`e.melee`, a flag now on each weapon entry — an **unarmed strike counts**, hence its null-weapon branch). The *follow-up attack* is the limited half, so it keeps a bonus-action card, renamed via a `displayName` on the subclass map entry to **"Marked Target"** — the trigger a player scans for mid-combat, not the feature name — and carries computed `subAttacks`, one per melee attack, with **half the Fighter level folded INTO the damage string** (it is one attack rolled once, so a trailing "+3" would read as a second damage source) plus a "with advantage" note. The card is **omitted entirely** when there is no melee attack row (bow-only), rather than shown with an instruction; bare-handed still gets it, since the unarmed strike is a melee row. **The ability term in both the to-hit and damage breakdowns names the RULE that chose it** (`weaponAbility` now returns a `reason`): 'DEX (ranged weapon)', 'STR (Finesse — STR ties DEX)', 'CHA (Hex Warrior)', or a plain 'STR' when no rule applies. Found in QA — a Finesse scimitar at STR 14 / DEX 15 showed a bare "+2 STR", the correct number but indistinguishable from the app hardcoding Strength. `addFlatDamage` gained a flat-damage branch for this: a base unarmed strike is "4 bludgeoning" with no die, and the old die-first regex turned +3 into "4 + 3 bludgeoning" instead of "7". **Riders are now COLLAPSIBLE** (via the shared `shared/FeatureNote.jsx`, which also backs the Items-tab equipment notes): name only, rules text on click (`ae-rider-{slug}` → `ae-rider-{slug}-text`) — a rider is a paragraph you need only once its trigger fires, and expanded ones bury the attack numbers the card exists for. Arcane Charge/Hold the Line/Vigilant Defender inherit this. **Riders that hang off WEAPON ATTACK cards are a data table, `ATTACK_RIDERS`** — `{source, scope:'melee'|'ranged'|'all', applies(ctx), text}` — consolidated at the point a third hand-written attach block would have appeared. Authored: **Unwavering Mark** (Cavalier L3+), the **Mounted Combatant** feat (melee only, gated on `hasFeat`) — both land on an unarmed strike too, since `scope:'melee'` follows the entry's `melee` flag — and the **Sharpshooter** feat (`scope:'ranged'`, both editions — Bypass Cover is the one clause the two versions share), the first rider that carries only PART of a feat — and now only its **cover** clause, because every other clause became a NUMBER on the same card: the long-range clause moved onto the range band (below), the −5/+10 is the power-attack toggle, and the within-5-ft rule was never Sharpshooter's (it is Crossbow Expert's, already handled by `spacingNote`). Cover stays prose because there is nothing to attach it to — the app has no distance-to-target model. One edition-neutral row serves both editions. A rider's **`text` may be a FUNCTION of the rider context**, not only a string — **Giant's Might** (Rune Knight, `scope:'all'`, so an unarmed strike qualifies) states a die that scales 1d6 → 1d8 (Great Stature) → 1d10 (Runic Juggernaut), which a static string could not. Its `applies` also gates on the effect actually RUNNING, not merely being earned: a rider is rules text read mid-swing, and a paragraph for a feature that is switched off is clutter on the surface a player scans fastest. Switching it on is what makes both the block and its damage term appear. It is a RIDER rather than part of the flat damage string for exactly the Sneak Attack/Divine Smite reason — it is once-per-turn — but unlike those the app now KNOWS whether it applies. A thrown handaxe keeps its melee card and so does NOT get it, the same line `isPureRangedWeapon` draws for the toggle. `text` is authored in the table because FEAT rules text lives only in the backend compendium and this module is pure. **Riders that attach to ONE NAMED entry are the sibling table, `ENTRY_RIDERS`** — `{source, entryKey, applies(ctx), text}`, matched by key across every bucket rather than by weapon scope, and applied LAST so a rider can target the universal menu (pushed last) as easily as a class feature. Consolidated at the same third-instance trigger, migrating the two hand-written blocks unchanged. Authored: **Arcane Charge** → Action Surge, **Hold the Line** → Opportunity Attack, the **Sentinel** feat → Opportunity Attack (its speed-0 + provoke-through-Disengage clauses; they were authored in the backend only as a display-only `note`, so the Reactions tab showed the unmodified stock rule text — found in QA), and the **Polearm Master** feat → Opportunity Attack (creatures provoke on ENTERING your reach — the same display-only-note gap). Polearm Master is the first **equipment-gated** rider, and the reason `applies` is handed the `inventory`: the clause is true only while a qualifying polearm is equipped, so it hides otherwise (matching how the feat's bonus-attack half is already gated) rather than telling a longsword user something false. It needs its OWN weapon predicate (`isPolearmReachWeapon(edition)`, not the bonus attack's `isPolearm`) because RAW the feat's two halves take **different** lists — 5e's reach clause drops the spear and adds the pike, and 2024 restates it as quarterstaff/spear/any Heavy+Reach weapon (so that edition tests properties, not names, and picks up homebrew polearms free). The compendium's seeded feat text flattens both halves to one list; the gate follows the rulebook. Rider `text` stays edition-neutral and names no weapons — the gate knows the list and the card only exists when you hold one. Sentinel is also the rider/entry line drawn twice in one feat: those two clauses MODIFY the opportunity attack, while **Sentinel Strike** fires on a different trigger (a creature within 5 ft attacking someone else) and is not an opportunity attack at all, so it stays its own Feat reaction entry — the same call Vigilant Defender got, minus `extraReaction` since it spends your normal reaction. Further OA riders (War Caster's cast-a-spell-as-an-OA, Mage Slayer) are now one-row data entries. **`RACIAL_ACTIONS` entries can be COMPUTED** — an entry may carry `compute({characterData, level, scores})` that derives its own detail from the character, plus a `resourceKey` into `RACIAL_REST_RESOURCES` (the tab merges racial resources alongside the class config's, so the card gets a Use button writing the same `<key>_used` as the Stats tab). Wired: **Dragonborn Breath Weapon** — damage (2d6→3d6@6→4d6@11→5d6@16), save DC (8+CON+PB), save ability and area all resolved from level + the stored `draconic_ancestry` via `race/breathWeaponData.js`, instead of the old static string that showed a level-1 card at level 16. **Grappler (feat, both editions) gets a `Grapple Attack` CARD, not a rider** (user's call: leave as little as possible to text) — `feat:grappler-attack`, one `subAttacks` row per weapon card carrying that attack's real to-hit + folded damage "with advantage"; it introduced two generic entry fields, **`origin`** (a badge naming where a card comes from, `ae-origin-{key}`) and **`requirement`** (an amber condition line the app can't check, `ae-requirement-{key}` — here "Only while you're grappling a creature", since there is no grappled-target state). The 2014 restrain is the feat's own `Pin: Restrain` action effect (it costs the whole action, so it can't share the card); 2024's Punch and Grab + Fast Wrestler are an ENTRY_RIDERS row on `universal:Grapple` whose text names the character's own size — entry-rider `text` may now be a function of the context (which carries `size`). **Grapple and Shove are cards in the universal menu**, from the new `combat/specialAttacksData.js`. They are deliberately NOT filed as actions: in neither edition is either one an action of its own (2014 calls them special melee attacks made in place of an attack; 2024 makes them two of the three Unarmed Strike options), so each carries the cost badge **"replaces one attack"** — badging them 'action' would teach that you must choose between grappling and swinging, when Extra Attack lets you do both. Each card computes its own **size line** (`ae-size-{key}`) from `creatureSize` WITH the active-effect context — "You are Medium — you can grapple a creature up to Large." — which is how a running **Giant's Might** moves the ceiling to Huge without the module knowing the rune exists, and is also **the only place the app prints the character's size**, the gap left open when the ActiveEffectsBanner was removed. The character's own size is stated FIRST because the limit follows from it. A grapple's free-hand requirement is a WARNING on the card (the Tavern Brawler shape — never a reason to hide it), and it is edition-aware: a 2014 shove needs no free hand while a 2024 one does. Entries carry a generic **`mechanicsSlug`/`mechanicsLabel`** that the tab renders as a "Learn more" link (`mechanics-learn-more-{key}`), reusable by any future entry whose rules outgrow a card. **The universal group's `ItemRow` previously received NO props at all** — found here, since its new link rendered `/campaigns/undefined/…`; it is now passed `campaignId`. **Spells now get a card EACH, filed under the action they cost** (they used to collapse to one "Cast a Spell" pointer per bucket to avoid clutter — collapsible source groups removed that constraint, and the pointer answered "can I cast something?" when the mid-combat question is "which of my spells is a bonus action?"). The new **`castableSpells({characterData, charClass, subclass, level, edition, race, subrace})`** resolves all FOUR sources the Spells tab shows — class lists, racial (cantrips + `getRacialSpellResources`), subclass (`subclass_cantrips` + `getSubclassGrantedSpells`) and feats (`getFeatGrantedSpells`) — as `[{name, source, resourceKey}]`, deduped with first-source-wins so a spell held twice is one card keeping its class attribution. **This closed the standing racial gap**: `characterSpellNames` read only cantrips/prepared/known, so a Tiefling's Hellish Rebuke — a *reaction* — was absent and the Reactions tab looked empty for a character who plainly had one. The tab's FETCH GATE uses the same resolver, or a character whose only spells come from a race/subclass/feat downloads no catalog and every spell is silently unclassifiable. A card carries level · school · Concentration · Ritual · "From {source}" (omitted for the class list, where it is noise), sorted cantrips-first then by level; a source that METERS the spell passes its `resourceKey` through (a racial once-per-rest, a feat's `free_cast`), so the card gets the standard Use control writing the SAME key the Spells-tab row writes — the WeaponAmmoControl arrangement. Ritual-book spells (Ritual Caster) are excluded: castable only as rituals, which is never a combat action, as are compendium-unknown spells and any casting time longer than a turn. Remaining: author `CLASS_FEATURE_ACTIONS_*` for the other 12 classes (+ more subclass features), establish the "rider" convention for no-action abilities (Sneak Attack, Divine Smite, Rage), and wire chosen options into the action economy (Battle Master maneuvers — now stored in `character_data.maneuvers`, Sorcerer metamagic, Warlock invocations — not yet stored).
