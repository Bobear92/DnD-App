# Active effects

How this system works today: features a character switches on and off.

> Moved verbatim out of CLAUDE.md on 2026-11-14 so it loads when needed instead of every turn. **This file is now the home for this material — update it here.** The standing rules that apply across systems stay in CLAUDE.md under "Character sheet rules"; what is still missing is in CLAUDE.md under "Frontend Not Yet Built".

- **Active effects (a feature you switch ON and OFF) — mechanism built, 5 entries authored** (Giant's Might, Channel Rune Frost/Hill/Storm, Samurai Fighting Spirit). Fighting Spirit added two generic pieces: an **`attackAdvantage`** grant (read by `buildActionEconomy` → an `ae-advantage-{key}` tag on every weapon attack card naming the effect) and an optional **`onStart(level, characterData)`** patch merged by `toggleEffectPatch(cd, key, on, {level})` — so BOTH spend points (the AE card, the rest tracker) write its temp HP, never just one. **RULE (user): anything named "Channel …" (Channel Rune, Channel Divinity) gets an active status, and while active it must DO something** — Hill's `resistances` grant lands on the Defenses card (via `activeEffectResistances` in defenses.js), Storm's prophetic state adds a `hidden`-gated **Prophetic State** reaction card that exists only while it runs; a bare Use counter that spends a charge and changes nothing is a bug (QA). Channels that are instantaneous or land only on the target (Cloud/Fire/Stone) have no self-state yet (`effects/activeEffects.js` + `ActiveEffectsBanner`). **This deliberately REVERSES the app's long-standing "no active-effect model" line** — the line that still keeps Rage damage, Divine Smite and spell-granted magic weapons as prose, because a bare "+2d6" on a card would be false most of the time. Rune Knight **Giant's Might** forced it: the feature changes the character's SIZE, grants advantage on two roll types and adds a scaling damage die, which is far too much to leave as a paragraph the reader applies by hand. State is `character_data.active_effects: string[]`; a definition is a data entry gated by class/subclass/level/edition, whose `grants(level, characterData)` returns only the fields it changes (`size`, `advantageAbilities`, `advantageSaves`, `reachBonus`/`reachSource`, `resistances`, `checkBonus`/`saveBonus` — each `{abilities, amount}`; every field needs a reader, enforced by `runeFieldReaders.test.js`) and whose `summary(level, characterData)` is its one-line description — so no surface retypes a number the definition owns. **Every grant must have a consumer, or the effect only pretends to do something**: QA found Giant's Might switched on, the banner announcing advantage on Strength checks and saves, and the Abilities & Skills panel completely unchanged — `advantageAbilities`/`advantageSaves` were produced and read by nobody. They are now wired to the two tables that already own those questions: `skills/skillAdvantage.js` gained an `active-effects` source (an ABILITY fans out to every skill keyed off it via the shared `SKILL_MAP`/`skillsForAbility` in `skillMath.js`, since RAW is "Strength checks", not "Athletics"), and `skills/saveFeatures.js` gained the Giant's Might entry with `advantageAbilities`. Check the same when adding an effect: a `grants` field with no reader is a silent no-op. **Duration is deliberately NOT modelled** (nothing tracks rounds): an effect runs until switched off, and the stated duration is text. **Spending an effect's charge ALWAYS switches the effect on, in ONE patch** — a counter that went down without the effect coming on is a use the player paid for and did not get. That rule now lives in the shared **`RestResourceControl`**, not in one caller: it takes an `activeEffect` (derived by the tracker from **`effectForResourceKey(row.key)`**, so no config edit can forget a row) and, while the effect runs, offers **End** instead of Use — ending never refunds. QA found the Action Economy card doing this correctly while the IDENTICAL row on the sheet's rest tracker was a plain counter, leaving `channel_rune_frost_used: 1` with `active_effects: []`. Two spend points for one charge with only one of them starting the effect is exactly what the single-patch rule exists to prevent, so put the rule in the control, not in the surface. The Action Economy card keeps its own richer toggle and suppresses the plain Use. A second always-visible `ActiveEffectsBanner` above the tabs was tried and **removed at the user's call** — a standing strip restating the effect's numbers over every tab was noise next to the card that already says it. Do not re-add it (preserved-intent rule). What a running effect changes is instead shown by the surface that OWNS each number: the skill/save `adv` tags (`skillAdvantage.js` / `saveFeatures.js`), the attack card's damage total, and the size that `creatureSize` resolves. **Known gap left by the removal:** creature **size** now has no display of its own again — it is computed (Heavy-weapon rule, `creatureSize` with the effect context) but nothing prints it, so growing Large is invisible on the sheet. Put it where size actually matters when that's worth fixing, not in a banner. `creatureSize(characterData, race, ctx)` now takes an optional effect context and resolves the grown size at that ONE function every consumer already calls, so the Items and Action Economy tabs can't disagree. A long rest resets the *charge* but deliberately does NOT switch the effect off (a 1-minute effect ended long before the rest; a rest clearing it would imply a duration the app doesn't model). **The second effect proved the model and extended it exactly as intended** — Rune Knight **Channel Rune: Frost** (10 minutes of +2 to all Strength/Constitution ability checks and saving throws) was a data entry plus two `grants` fields, no sibling table: `checkBonus`/`saveBonus` `{abilities, amount}`, because Giant's Might changes what you ROLL while Frost changes a NUMBER the sheet already prints. Abilities are named rather than skills (RAW is "checks that use Strength or Constitution"), so each consumer maps the ability to what it shows. It also added the `applies(ctx)` gate to `getActiveEffectDefs` (the defenses.js/saveFeatures.js escape hatch) — a rune effect is only offered while the rune is carved onto an EQUIPPED object, and numeric bonuses SUM across effects where advantage does not. Consumers: `activeEffectCheckParts(ability, ctx)` / `activeEffectSaveParts(ability, ctx)` return breakdown-ready `{key,label,value}` terms fed into `skillMath`'s new **`extras`** parameter by the skill rows and the Saving Throws grid, so a raised number always names its source in the click-to-see-the-math panel. **A moved number is not enough on its own** (a +7 Athletics with nothing beside it reads as the sheet's ordinary total), but **the marker must never be a second number**: a `+2` tag beside the total was tried in QA and read as "+7, and +2 on top of that" — the bonus is already inside the +7. So the affected row **colours its TOTAL indigo** instead (the existing `skill-bonus-{skill}` / `save-bonus-{ability}` values, no extra element), and each surface names the effect in words: the skills legend gains "Indigo total = includes {sources}", and the saves grid — which has no legend — gets a `saves-effect-note-{key}` line phrased as inclusion, "STR & CON saving throws include +2 from Channel Rune: Frost", never "+2 to …", for the same reason. Both come from `activeEffectCheckSources`/`activeEffectSaveSources` (grouped by source) and `activeEffectCheckBonus`/`activeEffectSaveBonus` (the per-ability total). Adding Rage/Hex/Hunter's Mark should be the same shape — check whether `grants` needs another field, not whether it needs a sibling table.
